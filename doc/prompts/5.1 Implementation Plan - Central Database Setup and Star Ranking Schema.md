# Implementation Plan: Central Database Setup, Profile Integration & Star Ranking System

Connect the oU1TS Portal (`/portal`) login and profile system to the centralized Supabase database shared with `ou1ts.github.io` and `ou1ts-backend`, establish a dedicated `public.stars` table with foreign keys and RLS, implement dynamic star ranking analytics across all JSON resource catalogs, and author a comprehensive step-by-step SQL setup guide.

## Proposed Changes

### Database & Schema Architecture
#### [`doc/query/query-4-central-db-portal-stars.sql`](file:///d:/GitHub/[oU1TS]/portal/doc/query/query-4-central-db-portal-stars.sql) & [`doc/db/portal_central_database_setup.sql`](file:///d:/GitHub/[oU1TS]/portal/doc/db/portal_central_database_setup.sql)
- Consolidate central database queries for execution in the Supabase SQL Editor:
  1. `public.profiles`: Central user profile table with student ID format checks, blood group validation, and `project_tags` array.
  2. `profiles_student_id_unique`: Partial unique index allowing multiple OAuth accounts while enforcing unique numeric student IDs.
  3. `public.handle_new_user()` trigger & `public.add_project_tag(tag)` RPC function.
  4. `public.stars`: Dedicated table storing `(user_id, resource_type, resource_id, created_at)` with unique constraints, cascade deletion on profile removal, and performance indexes.
  5. Row Level Security (RLS) policies: Public SELECT for star counts, owner-only INSERT and DELETE for authenticated users.
  6. `public.resource_star_rankings` view: Real-time dense ranking per category and global ranking across all JSON resource entries.
  7. RPC functions: `get_category_rankings()` and `get_user_star_metrics()`.
