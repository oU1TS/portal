# Future Implementation Specification: Portal AI Chat Drawer

This document outlines the design, user experience, and technical implementation plan for the **Portal AI Chat Drawer** feature for the oU1TS Portal.

---

## 1. Feature Overview

The **Portal AI Chat Drawer** is a conversational search assistant embedded within the portal. It allows students to query academic resources, capstones, mentors, and tools using natural language (e.g., *"Where can I find the CSE Batch 52 capstone projects?"* or *"Give me links for official UITS materials"*). 

### Key Capabilities
* **Natural Language Queries:** Translates user intent into direct navigation or resource suggestions.
* **Collapsible Sliding Drawer:** An slide-out interface that is reachable from any section of the Single Page Application (SPA).
* **Direct Navigation Actions:** In addition to replying with text, the assistant can provide interactive "Quick Action" buttons that route the user to specific SPA sections or open links directly.
* **Hybrid Search Strategy:** Uses either direct client-side search indexing (offline capable, zero-cost) or a serverless-proxied LLM (Gemini API) for advanced conversational understanding.

## 3. Technical Architecture

Since the oU1TS Portal is hosted on **GitHub Pages** (static hosting), we must avoid exposing private API keys (like the Google Gemini API key) in the client bundle. We propose two architecture options:

### Option A: Static Client-Side Search Indexing (Recommended - Free & Offline)
This approach runs entirely in the user's browser with no server cost or API key security risks.

```
[Local JSON Files] -> [Data Preloader] -> [MiniSearch / FlexSearch Index]
                                                     |
[User Query] -------------------------------> [Search Engine]
                                                     |
[Direct Results] <-----------------------------------+
```

* **Libraries:** Use a lightweight text-search library like **MiniSearch** or **FlexSearch** (loaded via CDN or local JS asset).
* **Indexing Mechanism:** 
  1. Upon page initialization or background worker load, fetch the static JSON structures: `materials.json`, `tools.json`, `courses.json`, `capstones.json`, `mentors.json`, and `talent.json`.
  2. Index documents with fields: `title`, `description`, `tags`, and target `route` (e.g. `#capstones`, `#materials`).
* **Query Matcher:** Performs fast prefix, fuzzy matching, and multi-field scoring. Translates queries like *"react tools"* into relevant cards under `#tools` and navigates the user.

### Option B: Serverless Proxied Gemini API (Advanced - Conversational)
This approach leverages Google's Gemini LLM for conversational search, securing the API key behind a free serverless function.

```
[Client Drawer] -- HTTP POST (query) --> [Vercel / Netlify Function] (Keeps GEMINI_API_KEY secure)
                                                     |
                                                     v
[Structured Response] <-- Stream Reply -------- [Gemini API] (gemini-1.5-flash)
```

* **Serverless Setup:** If migrating or proxying via Vercel/Netlify:
  * Deploy a single serverless endpoint (e.g. `/api/chat`).
  * Inject the `GEMINI_API_KEY` securely in the Vercel/Netlify dashboard.
* **System Prompting:** Inject repository context inside the LLM system prompt:
  > *"You are the oU1TS Portal Assistant. You help students find links. Below is the static list of all available categories and resources in the portal: [JSON Dump]. If a user asks for something, reply concisely, and output a JSON array of matching resource IDs or route hashes at the end of your response."*

### Step 2: Implement Client-Side Index Searcher (`js/ai-controller.js`)
Create a new controller to load data and run search indexing:

```javascript
class PortalSearchAssistant {
    constructor() {
        this.index = null;
        this.isInitialized = false;
    }

    async init() {
        if (this.isInitialized) return;
        
        // 1. Fetch data bundles in parallel
        const datasets = await Promise.all([
            fetch('json/materials.json').then(r => r.json()).catch(() => []),
            fetch('json/capstones.json').then(r => r.json()).catch(() => []),
            fetch('json/mentors.json').then(r => r.json()).catch(() => []),
            fetch('json/talent.json').then(r => r.json()).catch(() => [])
        ]);

        // 2. Format documents into unified search scheme
        const documents = this.normalizeData(datasets);

        // 3. Initialize MiniSearch index
        this.index = new MiniSearch({
            fields: ['title', 'description', 'tags', 'category'],
            storeFields: ['title', 'url', 'category', 'route'],
            searchOptions: {
                boost: { title: 2 },
                fuzzy: 0.2,
                prefix: true
            }
        });

        this.index.addAll(documents);
        this.isInitialized = true;
    }

    normalizeData([materials, capstones, mentors, talent]) {
        // Map different schemas into an array of search documents
        let idCounter = 1;
        const docs = [];

        materials.forEach(item => {
            docs.push({ id: idCounter++, title: item.title, description: item.description || '', tags: item.tags || [], category: 'Materials', route: '#materials' });
        });

        capstones.forEach(proj => {
            docs.push({ id: idCounter++, title: proj.title, description: proj.description || '', tags: proj.tags || [], category: 'Capstone Projects', route: '#capstones' });
        });

        // Add additional normalization loops for mentors & talent directories...
        return docs;
    }

    search(query) {
        if (!this.index) return [];
        return this.index.search(query);
    }
}
```

### Step 3: Integrate with SPA Router
* In `js/spa-controller.js`, when a user clicks a "Quick Action" suggestion bubble within the chat (e.g., `View Capstone Gallery`), the drawer should trigger:
  `window.location.hash = targetRoute;`
  This navigates the active SPA view immediately, keeping the chat drawer open or auto-closing it depending on viewport constraints.
