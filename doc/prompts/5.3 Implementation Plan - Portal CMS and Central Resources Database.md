# Implementation Plan: Portal CMS, Central Resources Database & Admin Role Management

Implement a complete Content Management System (CMS) for the oU1TS Portal that stores, approves, and auto-arranges community resources directly in Supabase without requiring manual edits to `json/*.json`, adds feedback management, establishes project-level admin role delegation with a user selector modal, and creates a comprehensive SQL migration script to populate the central database from all existing JSON catalogs.

## User Review Required

> [!IMPORTANT]
> - **Default Admin Selection:** You can designate any student as the first portal admin directly in the Supabase Dashboard by setting `is_portal_admin = true` on their record in `public.profiles`.
> - **Dual Loading Strategy:** The application will fetch approved resources from Supabase `public.portal_resources` first. If offline or if the database is unconfigured, it seamlessly falls back to the local `json/*.json` files.
> - **Featured Projects Automation:** Featured projects will be dynamically selected from the highest-ranked entries across all categories based on `public.resource_star_rankings`.
> - **Inspirations:** Institutional inspirations (`json/inspirations.json`) will continue to be manually curated as requested.

## Proposed Architectural Changes

### 1. Database Schema & SQL Scripts
#### [`doc/query/query-5-portal-cms-resources-schema.sql`](file:///d:/GitHub/[oU1TS]/portal/doc/query/query-5-portal-cms-resources-schema.sql) & [`doc/db/portal_cms_schema.sql`](file:///d:/GitHub/[oU1TS]/portal/doc/db/portal_cms_schema.sql)
1. **Admin Column on `public.profiles`:**
   - Add column `is_portal_admin BOOLEAN NOT NULL DEFAULT false` to `public.profiles`.
2. **`public.portal_resources` Table:**
   - `id TEXT PRIMARY KEY` (resource slug e.g. `materials-b1tacad`, `tools-b1tsched`).
   - `category TEXT NOT NULL` (`materials`, `tools`, `guidance`, `community`, `courses`, `portfolios`, `capstones`, `mentors`, `talent`).
   - `title TEXT NOT NULL`, `description TEXT`, `url TEXT`, `copy_url TEXT`.
   - `icon JSONB`, `links JSONB`, `tags TEXT[]`, `extra_data JSONB` (for flexible metadata: course rawHtml, capstone team/batch, mentor company/experience, talent sector/contacts).
   - `status TEXT NOT NULL DEFAULT 'approved'` (`pending`, `approved`, `rejected`).
   - `sort_order INTEGER DEFAULT 0`.
   - `submitted_by UUID REFERENCES public.profiles(id)`.
   - Performance indexes on `category`, `status`, and `sort_order`.
   - RLS Policies: Public read for approved resources; admins can insert, update, approve, and delete.
3. **`public.portal_submissions` Table:**
   - `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`.
   - `submission_type TEXT NOT NULL` (`'resource'` or `'feedback'`).
   - `title TEXT`, `category TEXT`, `submitter_name TEXT`, `submitter_email TEXT`, `submitter_department TEXT`, `submitter_batch TEXT`, `resource_url TEXT`, `details TEXT`.
   - `status TEXT NOT NULL DEFAULT 'pending'` (`pending`, `approved`, `rejected`, `reviewed`).
   - `created_at TIMESTAMPTZ DEFAULT NOW()`.
   - RLS: Any user can insert; only portal admins can view and update.
4. **RPC Functions:**
   - `public.get_portal_users()`: Returns all profiles where `'portal' = ANY(project_tags)` for the Admin User Selector Modal.
   - `public.set_portal_admin(target_user_id UUID, grant_admin BOOLEAN)`: Securely updates `is_portal_admin` (requires executing caller to be an admin).
   - `public.approve_resource_submission(submission_id BIGINT)`: Promotes a pending submission to `public.portal_resources` with a single call.
5. **Full Seed SQL Script:**
   - Generates SQL INSERT statements migrating all items from `materials.json`, `tools.json`, `guidance.json`, `community.json`, `courses.json`, `portfolios.json`, `official.json`, `capstones.json`, `mentors.json`, and `talent.json` into `public.portal_resources`.

### 2. Frontend CMS UI & Modules
#### [`js/cms.js`](file:///d:/GitHub/[oU1TS]/portal/js/cms.js) (New Module)
- **`CMS` Object:**
  - `init()`: Checks if current user is an admin (`Auth.currentUser?.isPortalAdmin`). If yes, renders the CMS button in the header and profile dashboard.
  - `openCMSModal()`: Opens full-screen glassmorphic management dashboard with 4 tabs:
    1. **Resource Approvals**: Review pending submissions with one-click "Approve" (auto-arranges to corresponding category) or "Reject".
    2. **Content Manager**: Browse, edit, delete, or manually add resources for any category.
    3. **Feedback Inbox**: Review Google Form / student `FEEDBACK` submissions with resolution status tags.
    4. **Admin Role Selector**: View all students who have logged into this portal (`Ecosystem Access`), with search and instantaneous toggle switches to grant/revoke portal admin status.

#### [`js/auth.js`](file:///d:/GitHub/[oU1TS]/portal/js/auth.js)
- Update `setUser()` to read `is_portal_admin` from Supabase profile:
  `isPortalAdmin: profile?.is_portal_admin || false`.
- If `isPortalAdmin` is true, trigger `CMS.renderAdminEntryPoints()`.

#### [`js/spa-controller.js`](file:///d:/GitHub/[oU1TS]/portal/js/spa-controller.js)
- Update `loadAndRenderView(pageType)`:
  - Query `public.portal_resources` from Supabase where `category = pageType AND status = 'approved'` ordered by `sort_order ASC, created_at DESC`.
  - If Supabase returns records, render them using `window.DataRenderer.render(pageType, data)`.
  - If offline or database empty, fall back seamlessly to local `json/${pageType}.json`.
- In `renderProfileView()`:
  - If user is an admin, render a prominent gold/purple **Admin CMS Portal** badge and launcher button.

#### [`js/data-renderer.js`](file:///d:/GitHub/[oU1TS]/portal/js/data-renderer.js)
- Update `loadFeatured()`:
  - Query top listings across all categories by joining `portal_resources` with `resource_star_rankings` or `stars_count`, matching the existing dynamic selection logic.
