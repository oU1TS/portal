# Walkthrough: Central Database Setup, Profile Integration & Star Ranking System

Connect the oU1TS Portal (`/portal`) login and profile system to the centralized Supabase database (`ou1ts.github.io` / `ou1ts-backend`), establish the `public.stars` table with Row Level Security, implement dynamic star ranking views across all JSON catalogs in `json/*.json`, and produce complete SQL queries and setup documentation.

## Changes Created & Updated

### 1. Centralized Supabase Database Queries
- Created [`doc/query/query-4-central-db-portal-stars.sql`](file:///d:/GitHub/[oU1TS]/portal/doc/query/query-4-central-db-portal-stars.sql) and mirrored in [`doc/db/portal_central_database_setup.sql`](file:///d:/GitHub/[oU1TS]/portal/doc/db/portal_central_database_setup.sql):
  - **`public.profiles`**: Contains student attributes (`id`, `student_id`, `email`, `full_name`, `department`, `batch`, `blood_group`, `social_*`, `project_tags`).
  - **Partial Unique Index**: `profiles_student_id_unique` enforces unique student IDs while allowing OAuth placeholders (`OAUTH_USER` or `NULL`).
  - **Trigger Function**: `handle_new_user()` auto-populates profiles on registration and attaches `['root', 'portal']` tags.
  - **RPC Tag Function**: `add_project_tag(tag TEXT)` appends the `'portal'` tag to the active user's profile upon authentication.
  - **`public.stars`**: Stores `(id, user_id, resource_type, resource_id, created_at)` with foreign key cascade to `profiles(id)` and unique constraint on `(user_id, resource_type, resource_id)`.
  - **Row Level Security (RLS)**: Public read access for star tallies, owner-only write and deletion.
  - **`public.resource_star_rankings`**: View computing category and global dense ranking for all resources across JSON catalogs.
  - **RPC Analytics**: `get_category_rankings()` and `get_user_star_metrics()`.
